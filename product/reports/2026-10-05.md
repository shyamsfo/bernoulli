## Decisions made this session

- **Dev backbone**: `Qwen/Qwen2.5-VL-7B-Instruct` (public, non-gated, fits L4 24GB in bf16).
- **No LiteLLM in the Scorer path.** Reason: the Scorer needs logits over label tokens + `allowed_token_ids` + prefix caching, none of which LiteLLM exposes uniformly. LiteLLM may still show up in `evals/baselines.py` for the generative baseline (M3).
- **AWS g6.xlarge, no auto-shutdown.** User explicitly chose ease > cost.
- **No GHA CI.** The interesting tests need GPU; GHA free runners can't run them. Real test runner = bernoulli. Clean-env guarantee comes from occasional `terraform destroy && apply`.
- **Deferred: Dockerfile.** Not useful until VLLMScorer lands in M4.

## Deviations from the vision doc

- Vision doc §6 lists a Dockerfile in the repo layout. Deferred to M4 (serving) — no value shipping an empty Dockerfile.
- Vision doc §6 lists `evals/` and `training/` top-level dirs. Deferred to M3 / M5 — same reason.

## Gotchas caught

- **AZ coverage**: us-east-1e doesn't offer g6.xlarge. Added `aws_ec2_instance_type_offerings` data source to filter subnets.
- **NVMe mount**: the NVIDIA GPU Base AMI already LVM-mounts the g6.xlarge instance-store at `/opt/dlami/nvme`. My first `user_data.sh` tried to `mkfs` it (LVM2_member error, masked by `|| true`). Fixed live and in-repo; convenience symlink `/opt/nvme → /opt/dlami/nvme` preserved for stable doc paths.
- **Terraform 1.5 vs 1.6**: local terraform is 1.5.7; lowered `required_version` to match.

# M2 session — Zero-shot HFScorer

Picking up right after M1 commit `30a81e1`.

## What was built

- **`bernoulli/labels.py`** — letter + Yes/No single-token discovery and startup assertion.
- **`bernoulli/prompt.py`** — chat template builder; state-first/question-last layout; `labels_for()` and `option_strings_for()` dispatch per question kind.
- **`bernoulli/scorer.py`** — `Scorer` Protocol + `HFScorer` concrete class (`Qwen2_5_VLForConditionalGeneration`, bf16/cuda, one forward pass per `score`, `allowed_token_ids` restriction, numpy out).
- **`bernoulli/decide.py`** — Request→Response dispatcher: builds the prompt, resolves label-token ids, calls the scorer, softmaxes, assembles the typed Decision. (New file, mild deviation from vision doc §6; noted below.)
- **`bernoulli/cli.py`** — `bernoulli decide --state X --question Y` CLI; loads config from env + flags, prints JSON.
- **Tests**: 37 total, 32 CPU-path + 5 GPU-marked. Deterministic-rerun check included.
- **CUDA torch pin** — pyproject uses `[tool.uv.sources]` to pull `torch` from PyTorch's `cu124` index on Linux x86_64; got `torch 2.6.0+cu124` on bernoulli.

## Decisions made this session

- **Letters A–I for ratings** (not digits). Qwen's tokenizer makes `" 1"`…`" 9"` two tokens — breaks the single-token-answer invariant. Letters are single-token for the full A–Z range, so we use A–I for ratings (max scale width 9).
- **Hard-code `Qwen2_5_VLForConditionalGeneration`** in `HFScorer`. Only one backbone in picture for M2–M3; a registry becomes worthwhile when M4 adds a second model class.
- **Defer `AutoProcessor` to M4** when images land. Qwen's processor hard-requires `torchvision`, and M2 is text-only; `AutoTokenizer` is enough.
- **CI tiering**: `make test-fast` for the CPU path (3.6s), `make test` for the full suite including GPU-marked (78.7s). The `gpu` marker auto-skips when CUDA isn't visible.
- **No `label_order` permutation in `build_prompt`** — scope creep for M2. The debiaser lands in M3 with the right API.

## Deviations from vision doc

- **§4 label scheme**: vision doc lists `" A"`…`" Z"`, `" 1"`…`" 9"`, `" Yes"`/`" No"` as single-token labels. Qwen's tokenizer disagrees on digits. Resolved with letters uniformly; recorded in CLAUDE.md decisions log.
- **§6 repo layout** adds `bernoulli/decide.py` not listed in the vision doc. Rationale: the dispatcher is non-trivial, cleanly separated from `scorer.py` (backbone concerns) and `server.py` (HTTP concerns).

## Gate status: M2 READY

Exit criteria met: CLI works end-to-end on the dev backbone across all three question types; tests green. Waiting for go-ahead on M3 (debias + calibration + eval harness).
