Methodology

What the numbers actually mean

Every metric answers a specific product-claim question. We run the same backbone (Qwen2.5-VL-7B-Instruct) both ways — Bernoulli reads single-token logits at the answer position; Generative asks in natural language and parses the completion. BGE-m3+LR embeds the input and fits per-task logistic regression on labeled data (500 examples).

Metrics

  • Accuracy, macro-F1 — top-1 label match.
  • ECE (10 bins) — Expected Calibration Error, JevBench convention. Lower is better; 0 is perfect calibration.
  • Brier — mean squared error of top-class probability.
  • NLL — negative log-likelihood of the gold label under the predicted distribution. The headline calibration metric; dramatically worse for the point-mass outputs of a text-and-parse pipeline.
  • Stability (reorder, reword) — fraction of examples whose top-1 is unchanged under option permutations and up to three paraphrased question stems. Binary skips reorder (Yes/No order is semantic, not positional).

Baselines

  • Bernoulli over HTTP against the running /v1/decide server. Reverse debias on choice; no debias on binary (Yes/No are semantic — reversing their order changes meaning, not position).
  • Generative over HTTP against the same server's /v1/generate. Same backbone, same prompt framing, parsed completion → point mass on parsed answer or uniform on parse failure.
  • BGE-m3 + LR — embed inputs with BAAI/bge-m3 (CLS pooling, L2-normalise), train scikit-learn's LogisticRegression on 2000 labeled training examples (seeded shuffle for class balance). Honest baseline for "could we have used embeddings?"
  • DeBERTa-v3-zeroshot — MoritzLaurer/deberta-v3-large-zeroshot-v2.0. The strongest open zero-shot encoder — NLI-tuned, which means it only scores ChoiceQuestion (natural-language label hypotheses); binary Yes/No tasks like PAWS are n/a by design. Produced on a one-shot Lambda A100 (sidesteps evicting the Bernoulli vLLM server on the dev box).
Honest caveats

What this run is not

Four things worth naming up front — the full engineering caveat list, with code references and per-benchmark footnotes, lives in benchmarks/README.md on GitHub.

  • Our evaluation, not an independent audit. Every result row carries a reproducibility footer (model revision, dataset hash, seed, hardware) so any number here can be reproduced or disproved. The JevBench submission is in the public leaderboard's queue for an external re-run; this page updates once that posts.
  • Dev-tier backbone. All numbers are from a 7B open-weight model on a single commodity GPU. A one-shot rental on a 32B production backbone (full writeup) lifted the hardest JevBench slice by ~18 points — expect every row here to improve on the production tier.
  • Not every baseline fits every task. DeBERTa-zeroshot is natural-language-inference-tuned so it only scores choice tasks (binary Yes/No like PAWS is n/a by design). Banking77's 77-way label space exceeds our single-pass alphabet, so stability under option reorder reads low on that one benchmark — architectural, documented per-benchmark.
  • CLINC150-OOS oos_auroc ≈ 0.48 for us. On the "none of these" probability story, we're at coin flip. BGE-m3+LR hits 0.78 — not by predicting OOS correctly (it never does, oos_recall 0) but because its softmax over the 150 in-scope classes carries enough signal for a well-ranked threshold. Likely prompt-framing + stem rewording on our side; investigation pending.
