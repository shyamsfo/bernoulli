# JevBench public cohort — Bernoulli (Qwen2.5-VL-7B) — 2026-10-08

First end-to-end run of the official JevBench harness against the running Bernoulli
server on the dev-tier backbone. Covers all three public splits
(`original` 72 · `easy` 48 · `hard` 111 = **231 tasks**). The private sealed cohort
is not included — that only runs when Benchmark Heaven re-measures the submission.

## Four-axis sketch (JevBench v1.4.2 scoring convention)

The composite JevBench Score is computed server-side; the four axes it blends are:

- **Intelligence** — chance-corrected accuracy per tier. Raw hits:
  - standard (= our `original`): 0.833
  - easy: 1.000
  - hard: 0.432
- **Calibration** — ECE on the hard tier is **0.264** (public-only; no sealed items).
  Easy ECE 0.003 confirms we're sharp when we're right; hard ECE 0.264 means we're
  overconfident where we fail. Native-probs path — Calibration counts.
- **Speed** — mean of score(p50), score(p95); scoring is `100 − 20·log10(s / 0.1 s)`.
  Weighted p50 ≈ 221 ms, p95 ≈ 964 ms (hard dominates, 111 of 231). Easy + original
  come in near the 100 ms sweet spot.
- **Cost** — `null` / self-hosted. The Cost column is reported as the amortised
  g5.xlarge spot price (~$1.01/hr for the A10G 24GB); the harness's ledger logs each
  reservation at the default placeholder `$0.02/decision` since Bernoulli's
  `reserve_estimate` is `0.0` (no marginal API tariff) and the Runner backfills a
  default reserve.

## What this says — in two sentences

Bernoulli delivers **100 % operational and schema validity across every public task**,
with native (not verbalised) probabilities and ~92 ms p50 latency on standard-tier
items — the structural promise of the Jev-class architecture, honoured end-to-end.
The 7B dev-tier backbone caps the reasoning headroom: easy is perfect, standard runs
at 83 %, and hard reasoning (tradeoff / temporal / probability / multi-hop) is where
the ceiling bites — the production step-up to Qwen2.5-VL-32B-AWQ (parked on AWS
capacity, tracked in `product/milestones.md` M4e) is the direct lever.

## Plausibility against the live board

The v1.4.2.2 leaderboard tops out at 67.37 (Imajev-4B) and the top-10 cluster is
58–65. The 7B dev-tier backbone here is not expected to rank there; the submission's
intent is to **establish the native-probs path works end-to-end on the official
harness** and to publish a reproducible baseline the production step-up can be
measured against. The Capability Score is useful as a **floor** — if it comes back
sub-30, the adapter translation is suspect and we should debug before celebrating.

Weakest family on `original` is **ordinal** (acc 0.333, Brier 1.22) — the
score-task mapping. The adapter translates JevBench's 0-indexed level codes to our
1-based `RatingQuestion` internally; this doesn't obviously look wrong, but the
scale distortion deserves a focused look before the next run. Tracked in
`product/parking-lot.md`.

## Reproduce

```bash
# bring the server up
ssh bernoulli 'cd ~/bernoulli && just serve'   # or `just docker-run` for the vLLM path

# run each split
for split in original easy hard; do
  ssh bernoulli "cd ~/bernoulli && uv run python -m benchmarks.jevbench.run \
    --tasks benchmarks/jevbench/upstream/datasets/public/$split.jsonl \
    --results benchmarks/jevbench/results/$split-2026-10-08.jsonl \
    --endpoint http://127.0.0.1:8000"
done

# summarise (upstream CLI; PYTHONPATH points at the vendored package)
for split in original easy hard; do
  ssh bernoulli "cd ~/bernoulli && \
    PYTHONPATH=benchmarks/jevbench/upstream uv run python -m jevbench.cli summarize \
      --tasks benchmarks/jevbench/upstream/datasets/public/$split.jsonl \
      --results benchmarks/jevbench/results/$split-2026-10-08.jsonl"
done
```
