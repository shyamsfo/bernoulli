# arXiv post-cutoff

4-way primary-category classification over arXiv papers published **strictly after** the backbone model's training cutoff. The whole point is anti-contamination: the model cannot have seen these papers at pretrain time, so classification performance reflects generalisation rather than memorisation.

- **Categories**: `cs.CL`, `cs.CV`, `math.PR`, `econ.EM` — chosen for maximal semantic separation (NLP vs vision vs probability vs econometrics).
- **Cutoff**: `BACKBONE_CUTOFF = "2025-01-01"` in `loader.py`. Default is safely after Qwen2.5-VL's pretraining cutoff (late 2023). Any paper with `publication_date >= BACKBONE_CUTOFF` is eligible.
- **Dataset**: `data/dataset.jsonl` (generated by `make_dataset.py` — see below). A 3-row `data/sample.jsonl` is committed for tests + leaderboard-structure validation; if `data/dataset.jsonl` is missing, the loader falls back to `sample.jsonl` with a warning.

## Why this benchmark exists

The post-cutoff claim is load-bearing — the whole benchmark is pointless if any example could have been in the backbone's pretraining data. Without this anti-contamination guard, every other benchmark result is open to the "the model memorised it" critique. This benchmark closes that loophole.

## Dataset construction

`make_dataset.py` queries the arXiv API, filters papers to `publication_date > BACKBONE_CUTOFF`, balances per-category counts, splits deterministically into `train`/`test`, and writes `data/dataset.jsonl`.

```bash
uv add arxiv
uv run python -m benchmarks.academic.arxiv_post_cutoff.make_dataset \
    --target 200 \
    --out benchmarks/academic/arxiv_post_cutoff/data/dataset.jsonl
```

**Backbone swap protocol** — when switching to a backbone with a later cutoff:

1. Update `BACKBONE_CUTOFF` in `loader.py`.
2. Re-run `make_dataset.py`; commit the regenerated `data/dataset.jsonl`.
3. Update the cutoff claim in `benchmarks/README.md` and each run's `results/latest.md`.

**Status**: `make_dataset.py` is skeleton-only in this commit (M8 task 10a). The actual arxiv-API fetch loop and the full snapshot land in M8 task 10b.

## State encoding

Each example's `state_text` combines title + abstract:

```
Title: <title>
Abstract: <abstract>
```

## Loader

```python
from benchmarks.academic.arxiv_post_cutoff import (
    BACKBONE_CUTOFF,
    CATEGORIES,
    QUESTION,
    REWORD_STEMS,
    load,
    load_train,
)

for ex in load(limit=100):
    ...  # BenchmarkExample(state_text, question=ChoiceQuestion over cs.CL/cs.CV/math.PR/econ.EM, ...)
```

The 4-option `ChoiceQuestion` uses the raw arXiv category strings (`cs.CL` etc.) as options; those are also used as the gold labels, so there is no label-string translation to track.

## Baselines applicable here

| Baseline            | Applies? | Note                                                                 |
|---------------------|----------|----------------------------------------------------------------------|
| `BernoulliHTTP`     | ✅       | Four options, letter-labeled (A-D), logit-read.                       |
| `Generative`        | ✅       | Same backbone, text completion parsed. Expect the backbone to recognise the categories without having seen the specific papers. |
| `DeBERTaZeroshot`   | ✅       | Choice over the four category strings. May need a different hypothesis template since the labels are codes rather than natural-language phrases. |
| `BGEm3LR`           | ✅ (if train has rows) | `.fit(load_train())` once. Empty training set skips the baseline column. |

Fine-tuned ceiling candidate: no obvious public arXiv-category fine-tune — this benchmark is uncommon enough that the fine-tune would need to be trained on the same split. Deferred indefinitely.

## Reword stems (stability test)

Three paraphrased stems in `loader.py :: REWORD_STEMS`. The stability runner swaps in each stem and compares top-1 answers against the reference run.

## Notes

- Not in the pre-M8 `evals/reports/` — this is a new benchmark introduced in M8.
- The "couldn't have seen it" claim depends on three things: (1) `BACKBONE_CUTOFF` being set correctly for the current backbone, (2) `make_dataset.py` honouring it strictly, (3) the arXiv publication dates in the committed dataset actually post-dating the cutoff. All three are mechanical; a reader can verify by inspecting `data/dataset.jsonl` against `BACKBONE_CUTOFF`.
